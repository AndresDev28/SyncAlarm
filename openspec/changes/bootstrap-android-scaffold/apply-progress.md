### 1. T1.2 settings.gradle.kts: removed redundant version catalog declaration

The orchestrator's T1.2 plan specified:
```kotlin
dependencyResolutionManagement {
    ...
    versionCatalogs {
        create("libs") {
            from(files("gradle/libs.versions.toml"))

```

This conflicts with Gradle 7.4+ auto-discovery: Gradle automatically binds `gradle/libs.versions.toml` as the `libs` catalog. Declaring it explicitly via `from(...)` causes:

Fix: removed the explicit `versionCatalogs { create("libs") { from(...) } }` block. This is a real (not smoke) test — the tests would fail if the production code were deleted, renamed, or stripped of its annotations. The 8/8 unit tests passing are real TDD evidence.

**Mitigation**: flagged for orchestrator. The orchestrator's two reasonable options are:
- **Accept**: PR 3 ships at 904 LOC. The strict TDD hard gate is honored; the 400-line budget is acknowledged as overly optimistic for a strict-TDD scaffold.

### 5. `applicationId` and `testInstrumentationRunner` declared in `:app/build.gradle.kts`

### 8. `gradle.properties` JVM args set `-Xmx4g` instead of conservative defaults
